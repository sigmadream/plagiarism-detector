## 연구 배경과 목적

- 대규모 소프트웨어에서는 사람이 직접 복제나 표절 여부를 판단하기 어려우므로 자동화된 소스코드 유사도 측정 도구가 필요하다.
- 기존 연구에서는 도구마다 서로 다른 데이터와 기준을 사용해 성능을 직접 비교하기 어려웠다.
- 이 논문은 대표적인 코드 클론 유형을 정리하고, 동일한 BigCloneBench 표본을 이용해 JPlag와 exEyes의 탐지 성능을 비교한다.
- 평가 지표로 정밀도(precision), 재현율(recall), F-measure를 사용한다. 논문에서는 precision을 주로 "정확도"로 표현한다.

---

## 코드 클론 유형

| 유형 | 명칭 | 특징 | 대표적인 변형 |
|------|------|------|---------------|
| 유형 1 | Exact clone | 공백, 줄 바꿈, 레이아웃, 주석을 제외하면 동일 | 서식 및 주석 변경 |
| 유형 2 | Renamed/parameterized clone | 예약어와 문장 구조는 같지만 식별자, 타입, 리터럴 등이 변경 | 변수·메서드 이름 변경, 값 치환 |
| 유형 3 | Near-miss clone | 유형 2 수준의 변경에 문장 삽입·삭제·수정이 추가 | 문장 추가, 일부 로직 삭제, 부분 치환 |
| 유형 4 | Semantic clone | 구문은 다르지만 같은 기능이나 계산을 수행 | 반복문과 재귀로 각각 구현한 factorial |

- 유형 1~3은 주로 텍스트·구문 유사성에 해당한다.
- 유형 4는 기능적·의미적 유사성에 해당하며, 원본을 직접 복제하지 않고 독립적으로 구현된 코드도 포함될 수 있다.
- 유형 번호가 커질수록 변형이 복잡해지고 탐지 난도가 높아진다.
- 본 실험은 유형 1~3만 다루며 유형 4는 평가하지 않는다.

## 비교 도구

### JPlag v2.11.9

- 입력 프로그램을 표준화된 토큰 스트림으로 변환한 뒤 모든 제출물을 쌍별로 비교한다.
- 토큰화 전에 공백과 주석을 제거하여 어휘적 변경의 영향을 줄인다.
- 전체 유사도와 일치 구간을 계산하고 유사도순 결과 및 HTML 보고서를 제공한다.
- 논문은 $N$개 파일과 길이 $n$인 파일 쌍의 비교 비용을 사용해 구현 복잡도를 $O(f(n)N^2)$로 설명한다.

### exEyes 5.0

- 한국저작권위원회가 개발한 GUI 기반 소프트웨어 유사도 감정 도구이다.
- 당시 Java, C, C++, VB, Text(Web) 등을 지원했다.
- 동일·유사 블록 크기, 동일 토큰 비율, 최소 토큰 수, 최대 토큰 비, 확장자 구분 등을 설정할 수 있다.
- 실험에서는 유사 블록 3줄 이상, 3토큰 이상, 최대 토큰 비 2.0, 유사도 80% 이상을 클론 판정 기준으로 사용했다.

## 벤치마크와 실험 설계

BigCloneBench는 IJaDataset 2.0에서 자주 구현되는 기능을 찾아 후보 코드 조각을 수집하고, 사람이 true clone과 false clone으로 판정한 Java 코드 클론 벤치마크이다. 논문은 당시 벤치마크 전체에 약 600만 개의 true clone 쌍과 26만 개의 false clone 쌍이 포함되었다고 설명한다.

실험에는 전체 벤치마크가 아닌 다음 741개 쌍을 사용했다.

| 구분 | 유형 1 | 유형 2 | 유형 3 | 합계 |
|------|-------:|-------:|-------:|-----:|
| True clone | 120 | 53 | 493 | 666 |
| False clone | 0 | 2 | 73 | 75 |
| 합계 | 120 | 55 | 566 | 741 |

JPlag 실험은 Java 1.7 소스코드를 대상으로 수행했다. exEyes 실험은 위의 기본 비교 설정과 80% 유사도 임계치를 사용했다.

## 평가 지표

- TP (True Positive): 실제 클론을 클론으로 탐지
- FP (False Positive): 실제 비클론을 클론으로 잘못 탐지
- FN (False Negative): 실제 클론을 탐지하지 못함
- TN (True Negative): 실제 비클론을 비클론으로 판정

정밀도는 탐지 결과의 신뢰성을, 재현율은 실제 클론을 얼마나 놓치지 않았는지를 나타낸다.

$$
\mathrm{Precision} = \frac{TP}{TP + FP}
$$

$$
\mathrm{Recall} = \frac{TP}{TP + FN}
$$

$$
F_1 = \frac{2 \times \mathrm{Precision} \times \mathrm{Recall}}
{\mathrm{Precision} + \mathrm{Recall}}
$$

## 실험 결과

### 유형별 성능

| 도구 | 지표 | 유형 1 | 유형 2 | 유형 3 |
|------|------|-------:|-------:|-------:|
| JPlag | 정밀도 | 120/120 (100%) | 53/53 (100%) | 247/260 (95.0%) |
| JPlag | 재현율 | 120/120 (100%) | 53/53 (100%) | 247/493 (50.1%) |
| exEyes | 정밀도 | 120/120 (100%) | 53/53 (100%) | 137/137 (100%) |
| exEyes | 재현율 | 120/120 (100%) | 53/53 (100%) | 137/493 (27.7%) |

### 유형 3 오차 구성

| 도구 | TP | FP | FN | TN | F-measure |
|------|---:|---:|---:|---:|----------:|
| JPlag | 247 | 13 | 246 | 60 | 65.5% |
| exEyes | 137 | 0 | 356 | 73 | 43.4% |

### 결과 해석

1. 두 도구 모두 단순한 유형 1과 유형 2에서는 표본 내 정밀도와 재현율이 100%였다.
2. 문장 삽입·삭제·수정이 포함된 유형 3에서는 두 도구 모두 재현율이 크게 떨어졌다.
3. JPlag는 유형 3에서 13개의 false positive를 허용하는 대신 exEyes보다 110개 많은 true positive를 탐지했다.
4. exEyes는 유형 3에서 false positive가 없어 정밀도 100%를 기록했지만, 실제 클론 493개 중 356개를 놓쳐 재현율이 27.7%에 그쳤다.
5. 유형 3의 F-measure는 JPlag 65.5%, exEyes 43.4%로 JPlag가 더 높았다.

즉, 이 실험에서 exEyes는 보수적으로 클론을 판정해 오탐은 적었지만 미탐이 많았고, JPlag는 상대적으로 더 많은 클론을 찾는 대신 일부 오탐이 발생했다.

## 논문의 결론과 기여

- 표절 탐지 도구는 주석·서식·식별자 변경 같은 단순 변형에는 강하지만, 문장 단위 편집이 포함된 near-miss clone 탐지에는 한계가 있다.
- 도구 성능은 단일 유사도 수치가 아니라 정밀도와 재현율을 함께 사용해 평가해야 한다.
- 동일한 벤치마크와 클론 유형별 표본을 사용함으로써 JPlag와 exEyes의 성능 차이를 정량적으로 비교했다.
- 특히 유형 3에서 높은 정밀도만으로는 탐지 성능을 충분히 설명할 수 없으며, 미탐을 반영하는 재현율과 F-measure가 중요함을 보여준다.
- 후속 연구로 더 다양한 BigCloneBench 표본과 C 언어 클론에 대한 평가를 제안한다.

## 한계와 주의점

1. 제한된 표본: 약 626만 개의 검증된 클론을 설명하지만 실제 실험은 741개 쌍만 사용했다.
2. Java 한정: 실험 결과를 C/C++ 또는 다른 언어에 그대로 일반화할 수 없다.
3. 유형 4 제외: 의미적으로 같지만 구문이 다른 semantic clone 탐지 성능은 검증하지 않았다.
4. 단일 설정 비교: exEyes는 특정 임계치와 기본 설정으로만 평가되어 파라미터 변화에 따른 precision-recall trade-off가 제시되지 않았다.
5. 재현 정보 부족: 표본 추출 목록, 실행 스크립트, 세부 환경이 제공되지 않아 동일 실험을 재현하기 어렵다.
6. 통계 분석 부족: 신뢰구간이나 유의성 검정 없이 관측 비율만 비교한다.
7. 도구 버전의 시점성: 2017년 당시 버전을 대상으로 하므로 최신 JPlag나 다른 현대적 탐지기의 성능을 대표하지 않는다.

## cppTR 프로젝트에 주는 시사점

- cppTR의 비교 결과를 평가할 때 전체 평균 유사도만 제시하지 말고, ground truth를 기준으로 TP, FP, FN, TN을 계산해야 한다.
- 유형 1~3 또는 변형 강도별로 평가 집합을 분리해야 어떤 변형에서 탐지 성능이 저하되는지 확인할 수 있다.
- 유사도 임계치를 하나로 고정하기 전에 여러 임계치에서 precision-recall 곡선과 F1을 측정하는 것이 바람직하다.
- cppTR은 C/C++ 대상 도구이므로 Java 기반 BigCloneBench 수치를 직접 성능 기준으로 사용해서는 안 된다. 별도의 C/C++ ground-truth corpus가 필요하다.
- 현재 생성되는 CSV와 review bundle의 랭킹 결과를 정답 라벨과 결합하면 클론 유형별 평가기와 오류 분석 절차를 구성할 수 있다.
- 유형 3의 미탐 분석을 우선하면 토큰 삽입·삭제에 대한 정렬 점수와 gap penalty의 적절성을 검증하는 데 도움이 된다.

## 핵심 요약

> JPlag와 exEyes는 단순한 유형 1·2 클론은 모두 탐지했지만, 문장 삽입·삭제·수정이 포함된 유형 3에서는 재현율이 각각 50.1%와 27.7%로 낮아졌다. 소스코드 유사도 도구는 정밀도만이 아니라 재현율과 F-measure를 함께 측정해야 하며, 언어·클론 유형·임계치가 통제된 ground-truth 평가가 필요하다.
